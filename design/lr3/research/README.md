# Исследование: юзабилити-тест и A/B-тест сайта CodeStart

Всё, что нужно для шагов 4–6 методички. Данные участников вносятся в CSV
после реальных сессий, расчёты делают скрипты `sus.py` и `ab_test.py`.

## Гипотезы

1. Кнопку «Выбрать курс» в hero замечают не сразу: рядом «Как мы учим» того же размера, а
   справа крупное фото, которое перетягивает внимание.
2. На мобильном пользователь не находит форму обратной связи с первого раза: «Контакты»
   спрятаны в бургер-меню, а кнопка «Войти» в шапке ведёт на ту же форму и путает.
3. Форма записи на странице курса на мобильном оказывается ниже программы — пользователь
   пролистывает всю страницу, прежде чем найти «Записаться».

## Метрики

| Тип | Что меряем |
|---|---|
| Поведенческие | время выполнения сценария, успех (да/нет), глубина скролла |
| Производительность | LCP, INP (в поле) / TBT (в лаборатории), CLS |
| Субъективные | SUS после сессии |
| Конверсионные | клики по CTA (событие `cta_click` в Clarity), отправка форм |

## Участники

- 18–35 лет, думают о смене профессии или первом курсе в IT
- пользуются интернетом каждый день, покупали онлайн-курсы или выбирали их
- устройство: 3 человека с телефона, 2 с ноутбука
- сайт CodeStart раньше не видели

## Сценарии

1. «Вы хотите записаться на курс по веб-дизайну. Найдите подходящий курс и оставьте заявку».
2. «Вы ищете информацию о преподавателе. Найдите страницу с преподавателем и посмотрите его курсы».
3. «Вы хотите связаться с администрацией. Найдите форму обратной связи и отправьте сообщение».

Сессия: Google Meet с демонстрацией экрана и записью, think-aloud, модератор молчит.
После каждой сессии участник заполняет SUS (`sus-form.md`).

## Файлы

| Файл | Что это |
|---|---|
| `protocol.csv` | протокол: участник × сценарий, время, успех, ошибки, комментарии |
| `sus-form.md` | 10 вопросов SUS для Google Forms |
| `sus.csv` | ответы SUS (1–5) по участникам |
| `sus.py` | расчёт SUS по формуле методички + средний балл |
| `ab-results.csv` | метрики A/B по участникам |
| `ab_test.py` | среднее, стандартное отклонение, t-тест Уэлча |

```bash
python3 sus.py sus.csv
python3 ab_test.py ab-results.csv
```

## Microsoft Clarity

1. clarity.microsoft.com → New project → имя `WebDesign-Lab3`, тип HTML.
2. Скопировать ID проекта и заменить `ВАШ_ID` во всех HTML в `site/` и `site-b/`:
   ```bash
   grep -rl 'ВАШ_ID' ../site ../site-b | xargs sed -i '' 's/ВАШ_ID/<ваш id>/'
   ```
3. Опубликовать обе папки на Netlify (перетащить `site/` и `site-b/` на app.netlify.com/drop),
   получить две ссылки A и B.
4. Через 2–3 часа после сессий смотреть: Heatmaps (Click, Scroll), Recordings,
   Rage clicks, Dead clicks, Quick backs. Фильтр по варианту: Custom tags → `variant`.
   Клики по CTA: Smart events → `cta_click`.

## A/B-тест

| | Вариант A (`site/`) | Вариант B (`site-b/`) |
|---|---|---|
| Кнопка в hero | «Выбрать курс» | «Начать бесплатно» |
| Цвет | синий `#2563EB` | зелёный `#047857` |
| Расположение | hero | hero |

Меняется только кнопка (текст и цвет), расположение то же — так разница в кликах относится
к самой кнопке. 20+ участников, по 10 на вариант, ссылка выбирается случайно.
